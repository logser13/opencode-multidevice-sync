# OpenCode V2 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver an isolated OMDS prerelease supporting V1 and tested V2 round trips.

**Architecture:** Separate generation-aware database detection and a V2 snapshot adapter from legacy serialization. Use a dual plugin entrypoint and keep V2 imports offline. Pin the acceptance runtime to OpenCode 2.0.29.

**Tech Stack:** TypeScript, Node SQLite, Vitest, local Git, OpenCode Windows CLI.

**Spec:** ../specs/2026-10-15-v2-compat-design.md

## Global Constraints

- Mutate only this isolated clone and disposable work fixtures.
- No private GitHub writes, global installations or live database writes.
- V1 and V2 formats cannot silently mix; no history pruning.
- V2 import requires offline confirmation and no journals.
- Test first, verify the full suite and inspect actual OpenCode API output.

## Review Focus

- Existing V1 rows in a mixed database must never mask V2 sessions.
- Event sequence collisions after continuation must be rejected or prevented.
- Import must not overwrite local projects, approvals or runtime service state.
- One bad shard or a divergent history must roll back the entire batch.
- Child sessions, Windows path mappings and partial histories must remain visible.
